Append dated entries; preserve previous observations. These inform work, but the user instruction and current design remain authoritative.

## 2026-09-23 — Prototype evidence and boundaries

- The existing Pi extension already plans checks and associates evidence with fingerprints. Compare actual behavior; do not claim invention of planning/invalidation.
- Complete npm declarations include bundled packages without their own URL/SRI. Require an actual containing package declaration and accepted ancestry; a bare `inBundle` flag is not an exemption.
- Real Conftest output nests violation metadata; its YAML parser treats unquoted `on` specially. Test semantic key equivalence and changed triggers with the actual evaluator.
- Aggregate success counts cannot prove expected controls were evaluated. A small private synthetic contract probe establishes the expected rule contract before candidate evaluation.
- Keep collector errors and known runner failures even when policy evaluation also fails. Missing evidence has precedence over known violation, but neither finding disappears.
- The approved fresh EER runner reached all eight suite loads and failed because generated Nuxt tsconfig was missing. Compatibility tests passed; Vitest executed zero assertions. A green synthetic demonstration does not make the real baseline green.

## 2026-09-24 — Operator comprehension and independent checkout

- Toni interpreted verbose `init` output as possible project defects. Init currently reuses the explanation report; deferred labels and large existing-untracked path lists obscure setup success. R1 tracks a focused UX correction, not an implemented fix.
- A new collaborator could not discover the design without the sibling rebaze checkout. Design ownership, architecture, roadmap and development instructions now live here. Historical paths remain dated evidence, not prerequisites.
- Test helpers accidentally depended on the author's Homebrew path and macOS binary digest. Synthetic fixtures must explicitly select the available evaluator and record its actual identity, while retaining failure on missing/incompatible tools and existing real-state pins.
- A full real-Vitest demo needs an actual local runner image. Bootstrap through the separate Docker reporter exercise and pass its printed immutable ID explicitly; do not assume an earlier machine's image exists.

- A fresh-collaborator review identified that rootful Linux Docker can create root-owned fixture lockfiles through a host mount. Synthetic manifest generation must use the host UID/GID; execution in the actual CLI remains governed by its separate non-root volume runner. The demo should validate an explicitly selected local immutable image ID before generating fixtures.
- Race-test instructions must include CGO and a C compiler. A successful macOS clean-copy run removes checkout dependencies but does not prove a Linux/other-architecture support matrix.

## 2026-09-24 — Release preparation

- A Preflight binary alone is insufficient for first-time initialization: release archives and Homebrew installation must carry the matching profile and policy files while retaining explicit trust selection.
- GoReleaser's archive glob handling must be verified against actual archive contents. The first recursive-looking docs glob selected only nested examples; explicit root/example mappings plus an archive smoke check caught and fixed the omission.
- Python unittest discovery requires importable test module names. Keep test filenames with underscores even when the executable helper uses a hyphenated filename.
- Homebrew App verification and release publication are separate: a successful release cannot supply a missing tap key, and token permissions do not prove that branch rules permit direct pushes. Keep a verified, no-rebuild tap retry path.
